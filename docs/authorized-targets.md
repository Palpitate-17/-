# 巡检目标授权与白名单

## 当前已上线范围

恒脑私有智能体由用户输入触发巡检；路由代码节点与 Cloudflare Pages 接口均只允许 `https://public-firing-range.appspot.com/`。实际请求固定为 `/`、`/mixedcontent/index.html`、`/clickjacking/index.html`，方法 GET。该站由 Google 作为公开扫描器测试靶场提供，见 [Firing Range 项目说明](https://github.com/google/firing-range)。本项目仅做低影响、只读、限量检查。**这条白名单已上线；以下新增目标流程尚未做成用户自助功能。**

## 新目标加入流程

1. 申请人提供准确的主机名、允许路径、请求方法、有效期、允许频率、授权人或公开靶场的官方测试政策链接。用户在聊天中说“我授权了”只是申请信息，不直接触发扫描。
2. 维护者核对申请人是否有权批准测试；公开网站仍需核对维护方明确公布的自动化测试范围。没有证据或范围不清时保持待审核。
3. 将核定范围写入**服务端**白名单，限制精确主机、协议、路径、方法、页数、字节数、超时、重定向和并发；记录到期与撤销时间。恒脑路由与报告校验同步更新，但模型侧白名单不能代替服务端控制。
4. 对已核定目标先做低影响试运行，并测试相似域名、子域名、不同端口、重定向、内网地址和超范围路径均被拒绝。检查响应与报告没有泄露凭据。
5. 到期、授权撤销或目标政策变化后，从服务端和智能体同时移除并复测拒绝行为。

加入新目标前，还需处理本地通用爬虫连接阶段的地址固定问题，避免仅在 DNS 预检时检查一次、实际请求却连接到其他地址。若采用平台服务端实现，应为每个被核定站点定义独立的静态目标配置。不要直接把任意用户输入网址传给云端请求函数。

## 演示和报告措辞

- 已上线：用户输入预设靶场，智能体当轮调用工具并返回当轮结果。
- 已本地验证：自有测试站的通用巡检、状态保存及跨轮复测。
- 尚未上线：用户自助添加授权网站、对任意真实业务网站的巡检、登录态或主动漏洞验证。
- 规则发现是待核实线索，不是已确认漏洞；`scan_status=partial` 时不能根据零发现得出安全结论。
