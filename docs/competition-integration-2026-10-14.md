# 企业命题 2：GitHub PR 对齐后的离线集成与提交边界

依据：第九届浙江省大学生网络与信息安全竞赛附件 1 安恒企业命题、附件 3 作品挑战赛说明。本文件记录 **2026-10-14** 本分支代码与实测，不代替正式作品报告或签字材料。

## 本轮采用的方案

以 GitHub `docs/hengnao-api-integration` 分支最新代码的 `POST /scan` 为入口，保留其精确路径白名单、API 鉴权、curl HEAD 观察、JSON/HTML 报告与首次/复测格式。在**相同 `/scan` 调用**中加入原团队的五个离线被动检测模块：可配置敏感规则、显式 Base64 凭据候选、DOM/正文基线、外链变化和本地黑名单、弱配置响应头/Cookie 检查。检测器只接收 `/scan` 已抓取的页面，不自行上网。低置信度/业务语境类命中保持 `verification=pending` 与 `severity=pending`，等待智能体或人工复核。

没有调用 DeepSeek、OSV/CISA 在线漏洞搜索、Nuclei 或主动漏洞利用。仓库历史上的 `prototype/vuln_intel.py` 仍存在，但本轮扫描路径不导入它。恒脑可沿用已有“API 工具 → 大模型整理”的 `/scan` 接口和 [当前提示词](hengnao-current-prompt.md)；本轮**尚未在恒脑账号里重新触发**该工作流，不能把本地测试写成新的恒脑实测。

## 2026-10-14 本机回归结果

环境：Windows、Python 3.11.15、从本地 `wheelhouse/` 使用 `--no-index` 安装 Beautiful Soup 4.15.0、PyYAML 6.0.3 及依赖；仅访问自建 `127.0.0.1` 临时站。`wheelhouse/` 与 `.venv/` 不入库。

| 脚本 | 实测结果 |
| --- | --- |
| `tests/check_local_api.py` | 通过；未授权/越权请求被拒，首次 3 页、3 条当前发现（1 条虚构敏感字段、2 条待核实弱配置），复测 2 条当前弱配置、1 条规则不再命中、1 条内容哈希变化；JSON/HTML/历史记录生成；进程内定时复扫通过 |
| `tests/check_team_modules.py` | 通过；首轮建立基线，忽略动态区域；加入合成编码字段和外链后得到 6 条待核实发现，移除后 6 条均记为不再命中；无外链请求、无原始合成值输出；HTML 报告生成 |
| `tests/check_public_mode.py` | 通过；公网范围测试完全使用模拟连接，不发送真实外部请求。该历史脚本还模拟了漏洞情报函数，但本轮 `/scan` 未使用该函数 |

上述数据是本地合成测试，不是对真实网站的漏洞检出率，也不证明恒脑在当前分支调用成功。两种被动头部检查可能指向同一配置问题，报告必须区分“数组条目数”与“独立漏洞数”。
