## 摘要

本作品构建了由用户发起的网站安全智能巡检智能体。用户在恒脑输入预先核定的测试目标后，路由节点确定受控扫描范围，工具节点调用 Cloudflare Pages 的即时巡检接口，服务端对预设页面执行只读 HTTP 请求与被动规则检查，报告节点校验本轮扫描结果并生成可读结论。当前已发布版本仅支持 Google Firing Range 公开扫描器测试靶场的三个固定页面；规则发现、响应头观察和混合内容观察均保留脱敏证据与待核实状态。另有本地通用巡检 API，已实现受控页面发现、SQLite 状态、跨轮复测和 JSON 报告，并在自有测试站完成闭环验证，但尚未部署接入已发布智能体。本作品以可复核的事实和明确的范围限制为核心，不把规则命中表述为已确认漏洞，也不把本地通用能力冒充为线上功能。

## 第一章 作品概述

### 1.1 背景与目标

网站巡检需要让操作人指定目标、获得本轮真实请求结果、理解发现依据，并在后续复测中区分当前命中和已消失条目。本作品的主要交付链是“用户发起一次巡检 → 恒脑工具即时请求 → 结构化结果 → 智能体报告”，定时作业仅保留为开发历史，不是当前交付的主要交互方式。

### 1.2 范围与边界

已发布智能体只允许 `https://public-firing-range.appspot.com/`，服务端只请求 `/`、`/mixedcontent/index.html`、`/clickjacking/index.html`。这是 Google 提供的扫描器测试靶场；本作品只进行低影响 GET 和被动观察，不跟随重定向、限制响应大小。其他网址由路由节点拒绝，接口也会返回 HTTP 400，不能仅凭用户输入扩大范围。新增公开靶场须核对维护方规则；用户声称已获授权的其他网站须先记录授权主体、域名、路径、方法、有效期和可执行测试类型，由服务端管理员核定后加入白名单。当前尚无第二个获核定并上线的目标。

## 第二章 作品设计与实现

### 2.1 已上线的按需链路

`用户输入 → 恒脑路由代码节点 → 自规划节点 → API 工具 → Cloudflare Pages /scan → 报告代码节点 → 结束节点`

恒脑私有智能体与私有 API 工具已发布；每次用户请求触发一次 `POST /scan`，请求体的 `target_url` 由路由节点给出。Pages Function 检查 API Key 与服务端白名单，再即时请求三个固定页面，返回扫描时间、执行状态、页面 HTTP 状态、规则发现和被动观察。报告代码节点校验数据类型、目标、页面范围和时间，只使用本轮工具结果。线上服务不依赖用户电脑、本机 Python API 或临时隧道。

### 2.2 已上线的检查和输出

当前服务端规则记录 `mixed_content` 等基于固定页面的发现；内置 `http_header_audit` 和 `html_resource_audit` 两项只读检查，分别观察安全响应头和 HTTPS 页面引用的 HTTP 资源。规则发现放在 `findings`，被动观察放在 `tool_checks[*].observations`。每项保留 URL、脱敏证据、待核实状态和条件式建议。`scan_status=partial` 表示有页面未完成，此时不能把空发现解释为安全。线上接口没有跨轮持久基线，因而不宣称已提供“本次已消失”或“内容变化”的线上判断。

### 2.3 本地通用模块

仓库另有 FastAPI 通用巡检 API、受控爬虫、检测模块、SQLite 状态与 JSON 报告。它在自有测试站执行过页面发现、状态比较和单条发现复测；本地实现支持的目标范围和测试方法由策略控制。该模块尚未作为公开稳定服务部署，也未接入已发布恒脑智能体。原始响应与调试数据留在本地或被 Git 忽略；密钥只通过私有配置传入，不进入源码或报告。

### 2.4 授权目标加入流程

白名单是服务端控制项。公开可访问不自动等于允许扫描；公开靶场应先核对维护方公布的范围和条款。其他目标即使由用户声明“有授权”，也先进入待审核清单。管理员核对证明及主机、路径、请求方法、速率和期限后，才更新服务端策略及恒脑路由，并做拒绝超范围目标的回归验证。撤销或到期时移除条目。此流程目前属于扩展设计，不应写成已上线的用户自助加站功能。

## 第三章 作品测试与分析

### 3.1 线上即时巡检

对固定 Google Firing Range 靶场执行的一次 2026 年 10 月 24 日线上验证返回 `scan_status=complete`、3 个页面、1 条规则发现、6 条响应头观察、0 条资源观察、0 个请求错误。该数据是单次测试快照，页面和响应头会变化，数量不作为固定预期；判断时应核对扫描时间、目标、每页状态与原始结构化字段。非白名单目标被服务端以 HTTP 400 拒绝。规则和观察均标记为待核实，不代表靶场有已确认的业务漏洞。

### 3.2 本地跨轮闭环

自有测试站的一次闭环验证中，首轮读取 9 页并输出 7 条发现；改变站点状态后的复测读取 9 页并输出 18 条发现，单条发现复测得到 `resolved`。更早的三页虚构演示可复现“当前发现 → 改动演示配置 → 规则不再命中并记录摘要变化”，但该演示不等于真实网站检测。本地评测集有 29 个案例，其中 25 个执行、4 个弱配置案例跳过；只在已执行的合成案例上得到 TP=19、FP=0、FN=0、TN=9，不外推到真实网站准确率。

### 3.3 自动检查

2026 年 10 月 24 日运行 `python -m pytest -q`，64 个测试通过；恒脑报告节点契约测试与 Cloudflare Worker 检查也通过。测试覆盖鉴权、范围拒绝、扫描输出、报告字段和部分失败状态。自动测试不能替代对真实业务站的人工授权及效果评估。

### 3.4 局限

已发布智能体目前只扫描固定靶场的三个页面。通用 API 尚未稳定部署；网页爬虫的网络边界还需进一步加固，才适合连接任意新目标。当前没有登录态巡检、主动漏洞利用、组件版本识别或线上跨轮基线。对未发现异常的页面只能说“本次规则未命中”，不能断言安全。

## 第四章 创新性与特色

本作品把服务端范围约束、即时工具调用、结构化脱敏证据和报告节点校验放在一条链上。模型承担解释任务，HTTP 状态和规则证据由工具产生，报告中保留待核实和部分失败状态。另一条本地闭环演示了跨轮复测的数据结构，但与线上交付严格区分。

## 第五章 应用场景与同类工具

适用场景是所有者明确许可、范围受限的低影响巡检，以及对测试靶场的教学演示。ZAP Automation Framework 提供更广的 Web 自动化扫描编排；Wazuh 文件完整性监控针对主机侧文件变化。本作品目前是一个受限的智能体调用与解释原型，未与上述工具做实测性能对比，也不取代它们。[ZAP 文档](https://www.zaproxy.org/docs/desktop/addons/automation-framework/)；[Wazuh 文档](https://documentation.wazuh.com/current/user-manual/capabilities/file-integrity/)；[Google Firing Range](https://github.com/google/firing-range)。

## 第六章 总结

已发布的恒脑私有智能体可以由用户输入触发对固定公开测试靶场的一次即时巡检，并返回有证据边界的报告。本地通用模块已完成受控巡检与复测验证，尚待安全加固、稳定部署和平台接入。正式交付时应以已上线链路做现场演示，以本地模块展示下一步扩展；报告、PPT、视频和代码说明必须用同一功能口径。
