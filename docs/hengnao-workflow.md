## 这个版本能做什么

用户手工输入授权范围和模拟巡检记录后，恒脑模型整理风险、证据、待核实事项与修复建议。它不会访问网站、发现页面或执行扫描。当前版本用于验证恒脑的低代码流程和结果表达，不能作为完整巡检系统提交。

## 工作流结构

```text
开始节点 → 大模型节点 → 结束节点
```

| 节点 | 当前配置 | 用途 |
| --- | --- | --- |
| 开始节点 | 必填输入参数 `input`，类型 `String` | 接收手工填写的模拟巡检资料 |
| 大模型节点 | 输入参数 `input` 引用 `开始节点.input`；模型为“恒脑安全垂域（快速决策）HengNao-v4”；Temperature 为 `0.2` | 根据输入整理结果；用户提示词通过恒脑变量选择器引用本节点的 `input` |
| 结束节点 | “回答内容”引用大模型节点的 `result_key` | 向用户显示模型生成的文字；不要选 `_error_code` |

模型节点的其他参数如未调整，可保留平台默认值。重建时以平台当前可用的模型名称和字段为准。

## 提示词配置

以下文本作为仓库中的基准版本。**提交或演示前，将这里与恒脑中实际保存的文本逐字核对并保持一致。**

### 系统提示词

```text
你是“网站巡检验证版”的结果整理助手。当前流程只分析输入中提供的模拟巡检资料；你没有访问网站、执行扫描或验证授权。不得声称自己完成了这些操作。

工作规则：
1. 只依据输入中明确给出的范围、状态码、页面内容和其他证据作判断。把用户填写的授权范围称为“提供的授权范围”，不要声称已独立核实授权。
2. 区分“模拟发现”“待核实”和“已验证事实”。当前流程的发现一律标注为“模拟发现，待核实”，不得写成真实网站已确认存在漏洞。
3. DEMO-ONLY、FAKE、TEST 等测试值不是真实密钥。可以说明“若真实密钥以同样方式暴露，会产生风险”，但不得据此判定真实密钥泄露、给出已确认的高危结论或要求立即轮换真实密钥。
4. 展示密钥、密码、个人信息等内容时遮盖中间部分，例如 api_key=DEMO-****。如果没有遮盖，不得称其“已脱敏”。
5. 不根据文件名、路径或状态码单独推断文件可被所有人访问；缺少访问权限验证时，写明需要核实。
6. 不编造未提供的页面、检测结果、法规条款或修复状态。没有足够证据时说明缺少什么。
7. 对于未观察到异常的页面，只写“本次资料未提供异常证据”，不得断言该页面没有风险。

请按以下格式回答：
巡检范围：提供的域名、路径，以及“仅分析模拟资料，未实际访问网站”。
风险发现：逐条列出类型、URL、脱敏证据、状态、判断依据、待核实事项和修复建议。正常页面无需强行报告风险。
结论：概括模拟结果，并说明下一步需要怎样验证。真实风险等级在完成验证前写“待定”。
```

### 用户提示词

在恒脑编辑器中，通过**变量选择器**插入大模型节点的 `input`。不要仅写文字 `input`，也不要手工猜测平台变量语法。文本结构如下：

```text
请分析以下模拟巡检资料，并按系统提示词要求回答：

[在此处使用恒脑变量选择器插入 input]

如果上方资料为空，直接回答“未收到巡检资料”，不要编造结果。
```

## 试运行样例

将以下内容粘贴到试运行的 `input` 框：

```text
提供的授权范围：https://demo.example.test/ 下的页面
说明：以下全是模拟数据，仅测试工作流；没有实际访问网站。

模拟检测记录 1：
URL：https://demo.example.test/public/config.txt
返回状态：HTTP 200
响应片段：api_key=DEMO-ONLY-12345
备注：DEMO-ONLY 是测试标记，不是真实密钥；尚未验证匿名用户是否可访问。

模拟检测记录 2：
URL：https://demo.example.test/about
返回状态：HTTP 200
未观察到异常。
```

验收结果：模型能读到 `config.txt`，把第一条写为“模拟发现、待核实”，遮盖测试值，并将真实风险等级写为“待定”；对 `about` 只说本次资料未提供异常证据；不声称已经访问或扫描网站。2026 年 9 月 28 日在恒脑试运行时，工作流已返回符合这些要点的分析。

## 已知限制与下一步

- 当前输入由人手工提供，缺少自动页面发现、真实检测、基线对比、告警和复测。
- 恒脑平台上的工作流目前无法从团队使用的界面导出；本文件用于手动重建和审阅配置，不能替代平台上的已保存实例。
- 下一步由 lcx 提供返回固定 JSON 的测试 API；wjy 在恒脑的「API工具」中验证调用，再把工具节点插入开始与模型之间。ljy 提供一条风险样例和一条正常样例，用于检查误报。
- 接入真实 API 后，模型的风险证据应引用工具返回的字段，不能仅引用用户输入。

## 重建步骤

1. 在恒脑创建一个低代码“智能体应用”，名称为“网站巡检验证版”，可见范围先设为用户私有。
2. 配置开始节点的必填 `input` 字符串参数。
3. 添加大模型节点，将其 `input` 引用到开始节点的 `input`；选择可用模型，设置提示词并通过变量选择器插入输入值。
4. 把节点按“开始 → 大模型 → 结束”连线；结束节点的回答内容引用大模型的 `result_key`。
5. 使用上面的虚构样例试运行，核对输出，再保存。
