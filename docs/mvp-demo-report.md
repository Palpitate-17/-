# 网站安全巡检 MVP：本地演示与复测报告

## 一、演示范围与数据性质

本次演示目标为团队自建的本机测试站 `http://127.0.0.1:8765/`。巡检程序实际向该地址发起 HTTP 请求；站点页面、配置文件及其中的 `api_key=DEMO-ONLY-12345` 均为虚构测试数据。API 返回的 `simulated: false` 表示发生了本机 HTTP 请求，`data_kind: synthetic_local_demo` 表示被访问的数据属于本地虚构演示内容。**本次没有检测真实业务网站，也不能据此认定真实密钥泄露。**

本地 API 通过临时 HTTPS 隧道供恒脑工作流调用，工作流依次执行“开始节点 → 巡检工具节点 → 大模型整理节点 → 结束节点”。大模型只整理巡检 API 的结果，不独立验证漏洞。

两次读取的页面为站点首页、`/about.html` 和 `/public/config.txt`，返回状态均为 HTTP 200。状态码只说明本机演示请求获得响应，不能证明真实环境中的访问控制情况。

### 首次巡检：命中演示标记

巡检工具在 `http://127.0.0.1:8765/public/config.txt` 中命中 `sensitive_exposure` 规则，并仅输出脱敏证据 `api_key=[REDACTED]`。该条目的 `verification` 与 `severity` 均为 `pending`。这是虚构配置内容触发的规则结果，**不属于已验证的真实风险**。

### 复测：标记消失且内容发生变化

演示人员将该文件改为 `# Local demo: issue removed` 后，再次调用同一个本地巡检 API。复测结果中的 `findings` 为空；首次命中的条目进入 `resolved_findings`；`changes` 记录了该文件的 SHA-256 摘要变化：`eacf4798f169 -> 99f08626a6e3`。

这里的“已消失”表示**本地规则在复测时不再命中**，并非对真实业务系统完成修复验收。内容变化由本次演示中主动修改文件引起，不能称为未授权篡改。文件在复测时仍返回 HTTP 200；本次演示清除了测试标记，没有演示撤销该文件的公开访问权限。

## 三、MVP 已验证的能力

1. 在限定的本机目标上读取页面并返回 URL、HTTP 状态与巡检结果。
2. 对虚构敏感字段进行规则识别，输出脱敏证据，不在结果中暴露测试值。
3. 保存前一次结果作为基线，在复测时区分当前发现、已消失发现与文件内容变化。
4. 由恒脑工作流调用本地巡检 API，并将结构化结果整理为中文报告。

## 四、证据与后续工作

- 复测原始结果：仓库根目录的 `demo-result.json`（本地生成文件，不作为真实站点检测证据）。
- 本地 HTML 展示：仓库根目录的 `demo-report.html`（本地生成文件）。
- 恒脑首次巡检与复测的文字结果已归纳在本报告中；演示时可直接重新运行工作流展示。

下一阶段应在取得明确授权和测试范围后，再设计真实站点的目标约束、访问控制验证与风险复核流程。当前 MVP 仅证明本地虚构场景的“发现 → 修改 → 复测 → 报告”链路可运行。
